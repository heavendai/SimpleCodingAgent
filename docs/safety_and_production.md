# 安全边界与生产差距

## V01–V10 确实实施的限制

- 每次演示使用新样例副本；工具只允许仓库相对路径
- 拒绝父级跳转、绝对路径、指向仓库外的符号链接，以及请求路径或解析后路径里的隐藏文件
- 仅 `stats.py` 能通过 patch 修改，不能改测试“作弊”；旧文本必须精确且只出现一次
- 没有通用 shell 工具；测试命令是固定参数列表，`shell=False`
- 子进程不继承整套环境变量；提供 5 秒 timeout，截断回传输出
- 模型调用数、工具调用数、累计模型输入输出字符数有上限；主/子角色共用预算
- 精确授权由 host 保存，模型没有“批准自己”的工具
- 接受完成声明前，检查测试结果与当前工作区文件指纹
- checkpoint 恢复前检查可见文件完整性；大于检索长度限制的文件也纳入指纹

## V01–V10 为什么仍然不是沙箱

允许 `python -m unittest` 就允许执行 Python。被测试代码、导入代码和测试文件本身都能读取进程可见文件、连接网络、启动子进程。`cwd`、禁用 shell、路径白名单、移除环境变量都不能改变操作系统赋予进程的权限。

因此只对本项目可信的离线样例运行。接入真实大模型后，生成代码也是不可信代码，即使初始仓库可信，也应在真正隔离的环境里测试。官方沙箱设计同时强调文件系统、网络与衍生进程边界。[Anthropic sandboxing](https://www.anthropic.com/engineering/claude-code-sandboxing)

原 V01–V10 没有系统沙箱。V11 新增 Bubblewrap profile，详见下节；项目仍没有 VM、自定义 seccomp、cgroup 聚合资源配额或通用 host 文件工具的抗竞态设计。检查符号链接后再访问文件仍有 TOCTOU 风险。不要让恶意进程同时改这个工作区。

## V11 已实现与尚未验证的边界

新增 Linux Bubblewrap 执行后端：固定两文件只读快照、只读系统运行时、独立 PID/network/user/IPC/UTS namespace、无凭据环境、只读根/最小设备、受限 tmpfs、继承 hard rlimits、流式输出上限和超时监督。探测或设置失败立即 `blocked_sandbox`，禁止回退 host；证据与 checkpoint 绑定 backend。host read/search/patch、模型 API 和外部工具不自动获得隔离。

当前云宿主拒绝 NETLINK_ROUTE socket，真实隔离集成测试未执行。单测通过不等于活体边界已验收。资源限制是每进程/real UID 范围，不是整个 sandbox 的 cgroups 配额；共享内核，不防未知内核漏洞。详细威胁模型、参数、验证状态和操作见 [V11](11_sandbox.md)。

## 各项简化的准确含义

### 上下文

`compact()` 压缩旧 history，保留结构化 facts 和最近两条观察；不保证总上下文小于某个固定长度。读取上限是每文件 32 KB、检索目录最多 100 个文件、搜索最多返回 20 项。V10 的累计字符预算是额外停止条件，**字符不等于 token，也不等于美元成本**。

生产系统还需按 token 计算窗口、检索排序、按行/分块读取、跨文件符号索引、facts 过期与摘要质量测试。仓库说明和 skill 都只能是低信任任务上下文，不能授予权限。本项目用确定性 mock，未进行真实 LLM prompt-injection 鲁棒性评测。

### 时间和输出

总 wall-time 预算在操作边界检查，是协作式截止时间，不能硬中断正在运行的操作。测试子进程 timeout 为 5 秒；可选 API 请求 timeout 为 20 秒。单次操作可能超过全局剩余时间。V01–V10 测试输出是在进程结束后截断回传；`capture_output` 不是内存级输出限额，因此也不能运行会无限输出的不可信程序。

### 测试与验收

提供的 4 项单元测试是真实执行的；成功只说明这些测试通过，不证明任意输入或实现正确。独立 grader 使用额外的 5 组输入，仍然只是玩具回归。测试开始和结束时指纹必须一致，结束声明还会再次检查。这里没有文件锁，因此并发恶意修改不在保证范围内。

### 持久化与恢复

checkpoint 用临时文件、flush/fsync 和 replace 保存 JSON。包含任务状态、预算、工作区位置和可见文件指纹；不包含 API key。文件指纹忽略隐藏路径和 `__pycache__`，记录可见符号链接的目标字符串，不跟随读取它们。

恢复是**继续已保存的执行状态**，不是回滚磁盘、撤销 API 副作用或任意时刻的 exactly-once 执行。补丁写入和 checkpoint 写入不是同一事务；进程恰好在二者之间崩溃时会因文件不一致而拒绝自动恢复，需要人工核对 diff。demo 的暂停点都在一次完整保存之后。生产系统应使用事务日志/操作 ID、幂等策略，以及 Git/worktree 或文件快照。[Checkpointing 官方边界](https://code.claude.com/docs/en/checkpointing)

### 子 Agent

reviewer 有独立 State，暴露的工具只有 read/search，主 worker 是唯一写入者。reviewer 仍是手写规则模型，仅检查样例的空输入 guard，不是正式代码审查器。没有并行写入、分布式队列、自动合并或 agent 共识协议。主/子角色共享预算，并非通过委派免费扩大调用额度。

### 日志与隐私

本地 JSONL 与 checkpoint 会包含样例代码和工具输出。没有生产级脱敏或访问控制；不要把敏感仓库放进样例工具里，再把日志发给别人。可选真实模型会发送选中的上下文到 OpenAI API；`store=False` 只是 API 参数，不等于本地日志已脱敏或服务端所有合规保留都关闭。

## 从教学骨架走向真实业务

按依赖顺序建设：

1. 在支持隔离的受控环境完成 V11 的活体验收，再补生产级 cgroups/seccomp/VM、网络策略和秘密管理
2. 以真实模型替换 demo policy，保留动作 schema、权限检查和独立验收
3. 加入真实仓库样本、未暴露给模型的验收测试、多轮 trials 和失败分类
4. 增强局部上下文、技能检索、语法/LSP 信息与压缩质量
5. 完善 Git/worktree、操作幂等、恢复与人工介入 UI
6. 对外部工具逐个审查权限与数据流，再扩展 MCP、IDE、issue/PR 集成
7. 在同一模型、环境与预算下消融比较计划、多角色、路由等机制

这些是本项目的后续路线，不是已经部署或通过验收的生产功能。
